# AI 처방·리팩토링·검증 안내

2026-10-20 갱신(웹 재설계), 2026-10-25 '한 번에 깊게' 추가. 고정 실험, 과거 CLI AI 예시, 최종보고서와는 별도의 기능입니다. 설계 근거는 [웹 재설계 설계서](superpowers/specs/2026-10-19-web-redesign-design.md)에 있습니다.

## 흐름

1. **엉킴 진단**에서 오른쪽 **AI 처방 받기**를 누릅니다. 버튼을 눌렀을 때만 요청하며, 받은 처방은 저장해 다시 보여줍니다. 분석이 바뀌면 ‘이전 분석 기준 처방’으로 표시합니다.
2. AI에는 코드 전체가 아니라 **구조 요약**(파일별 점수·원시 지표·연결 수·순환 고리 여부·정리했을 때 빠지는 파일 수·복잡한 함수)과 주요 파일의 **선언부 발췌**(헤더 등, 파일당 4KB 이하)를 보냅니다. 전체 80KB 이하이며 화면에 보낸 크기를 표시합니다.
3. AI는 먼저 정리할 파일을 **최대 5개** 우선순위대로 고르고, 각각을 **연결 정리**(다른 파일과의 연결을 끊음) 또는 **파일 안 정리**(함수 분리·중복 정리)로 구분해 이유·방법·기대 효과를 존댓말로 쓰고, 먼저 정리할 **대상 함수**(최대 3개)를 이름으로 지목합니다. 정밀 분석(Clang)은 실제 호출·참조로 연결을 세므로 `#include`만 옮기는 처방은 숫자가 거의 바뀌지 않아, 큰 함수를 나누는 처방을 우선하도록 안내합니다. 정해진 형식을 어기면(없는 파일, 6개 이상, 중복, 반말, 너무 긴 문장) 1회 다시 요청하고, 그래도 어기면 실패로 표시합니다.
4. **숫자는 프로그램이 계산합니다.** ‘지금 상태 43 → opentyr 정리 후 22’처럼 순환 고리 변화는 의존 그래프에서 해당 파일의 연결을 끊었다고 가정한 최대 기대치이며, 실제 값은 적용 후 다시 분석해 확인합니다. 계산상 줄지 않으면 경고합니다. 제목 문장과 ‘왜 점수 1위가 아닌가요?’ 설명 여부도 계산 결과로 정합니다.
5. **추천대로 진행** 또는 **직접 고르기**로 **AI 리팩토링**에 들어가 변경안을 만듭니다. **변경 방식**은 두 가지입니다.
   - **한 번에 깊게(기본)**: 파일마다 AI를 따로 부르고 고른 파일(최대 5개)을 모두 동시에 진행합니다. 각 AI는 자기 파일과 같은 이름의 헤더(읽기 전용)를 받으며, 파일과 헤더가 300KB 이하면 통째로, 더 크면 **대상 함수의 본문 전체**와 파일 앞부분·다른 함수 일부를 보냅니다. 대상 함수는 잘라 보내지 않으며, 너무 커서 담지 못한 함수는 '보내지 못한 함수'로 표시합니다. AI는 대상 함수를 의미 단위의 정적 보조 함수로 나눠 분기 수를 크게 줄이도록 요청받고, 자기 파일의 함수 본문만 바꿀 수 있습니다(새 헤더·함께 수정 파일 없음). 파일마다 아래 규칙으로 따로 검사하고 통과한 파일만 하나의 변경안으로 묶습니다. 거절되거나 25분 안에 시작하지 못한 파일은 이유와 함께 표시되고, **이 파일만 다시 만들기**로 같은 변경안에 더할 수 있습니다. 자동 재시도는 하지 않습니다. 진행 화면은 파일마다 상태(대기·작성 중·검사 중·완료·바꿀 곳 없음·거절)와 보낸 양을 보여 줍니다. 파일 하나의 AI 응답 제한은 15분입니다.
     - **이어서 정리:** 답 하나는 대상 함수 2개에서 약 400줄·보조 함수 6개 이하만 옮기고(답마다 출력 상한 3만 2천 토큰), 대상 함수가 아직 크면(복잡도 40 이상) 같은 파일을 최대 3번까지 이어서 AI에게 넘깁니다. 단계마다 그 단계의 변경과 원본 기준 전체 변경을 모두 검사하고, 통과한 단계까지만 남깁니다. 한 단계가 분기를 거의 줄이지 못했거나(5개 미만이거나 5% 미만) 파일을 시작한 지 15분을 넘길 것 같으면 멈춥니다. 앞 단계에서 만든 보조 함수를 뒤 단계의 새 보조 함수가 부르는 것은 허용합니다(대상 함수에서 새 보조 함수를 거쳐 닿으면 됨).
     - **모델:** 변경안은 처방대로 함수를 나누는 일이라 가벼운 모델로 충분하고 사용 한도를 훨씬 적게 씁니다. 화면은 단계와 AI마다 추천 모델을 채웁니다(Claude 처방 = 기본(Opus), 변경안 = `sonnet` / Gemini `pro`·`flash` / Codex는 기본 모델에 가벼운 모델 버튼). 2026-10-26 실측(OpenTyrian 5개 파일, Claude Code `sonnet`): 7분 48초, AI 호출 13번(이어서 정리 포함), 입력 약 160만·출력 약 30만 토큰, 5개 파일 모두 통과, 컴파일 오류 0.
   - **파일 사이 연결 정리**: 고른 파일을 한 번에 보내(합계 240KB 이하는 통째로, 넘으면 관련 구간 발췌) 공용 헤더를 나누거나 `#include`를 정리합니다. 그 파일을 부르는 파일들의 `#include`/`using` 부분도 보냅니다.
   C/C++는 구현 파일과 같은 이름의 헤더도 함께 보냅니다. 1MB가 넘는 소스 파일은 AI에게 보내지 않습니다.
6. 변경안 화면은 전체 요약(문제·이유·방법·효과), 파일 목록(처방 대상 / 함께 수정되는 파일 / 새 파일), 원본↔수정본 비교, 파일별 AI 소견으로 구성됩니다. AI의 설명은 문장마다 줄을 나누고 첫 문장을 굵게, 파일·함수 이름은 코드 글꼴로 보여 줍니다(내용은 줄이지 않음). '한 번에 깊게'의 전체 요약은 프로그램이 파일별 설명을 `[파일 이름]`으로 이어 붙인 것입니다. **이 변경안 적용하기**를 누르면 원본을 그대로 두고 사본에 적용한 뒤 다시 분석합니다.
7. **수정 결과·검증**에서 먼저 고친 함수의 전후 복잡도(CC)·길이와 감소율(가장 크게 줄어든 함수를 크게, 새로 만든 함수까지 합친 값도 함께)과 **코드가 이렇게 바뀌었습니다**(바뀐 함수마다 원래 코드와 고친 뒤 코드를 나란히, 새로 만든 함수 포함), 안전 확인 줄(검사 규칙 통과·원본 보존·승인한 변경과 동일·다시 분석·빌드·동작 비교·직접 플레이, 자세한 내용은 펼쳐 보기)을 확인합니다. 그 아래 파일 점수 표와, 게임 전체 기준 보조 지표인 엉킴 총량(처음 = 100, 한 라운드에 보통 2% 미만 움직임)·순환 고리·연결·매우 복잡한 함수·초과 복잡도가 있습니다. 등록된 시연 게임은 **수정된 게임 실행**으로 바로 실행합니다. 직접 해 본 결과는 버튼으로 기록합니다.
8. **다음 처방 받기**로 이 수정본 기준의 진단·처방을 다시 받습니다(라운드). 다음 처방을 요청할 때는 이전 라운드에서 바뀐 파일 목록과 현재 엉킴 총량도 함께 보냅니다. 라운드는 이전 수정본 위에 쌓입니다. 최신 라운드는 되돌릴 수 있고, 되돌린 라운드는 그 뒤 새 라운드를 적용해도 `discarded` 기록과 파일로 남습니다. 되돌리기 전에 만든 변경안은 되돌린 뒤 적용할 수 없으며, 변경안은 만든 라운드에서만 적용됩니다.
9. 적용할 때 수정본 소스 파일의 지문(`manifest.json`)을 기록합니다. 시연 게임은 빌드 전에 이 지문과 맞는지 확인합니다. 라운드 기능 이전에 만든 작업은 처음 열 때 적용된 수정본을 1라운드로 옮겨 기록합니다.

처방과 변경안을 만드는 중에는 **요청 취소**를 누를 수 있습니다. 그 요청이 실행한 AI 프로그램만 멈추고, 고른 파일과 이전 처방은 그대로 남습니다. API 키 방식은 이미 보낸 요청의 사용료가 청구될 수 있으며 결과만 버립니다.

## 변경안 검사 규칙

| 대상 | 허용 | 프로그램 검사 |
|---|---|---|
| 처방 대상 · 함수 정리(functions) | 선언한 기존 함수 안의 변경, 설명에 이름이 있고 실제로 호출되는 새 정적 보조 함수 | 바뀐 줄이 선언한 함수 범위 안인지, 새 함수가 static이고 호출되는지(문법 트리) |
| 처방 대상 · 선언 정리(declarations) | 기존 자료형·매크로·원형·선언 줄을 다른 헤더로 **옮기기**, `#include` 줄과 `struct X;` 같은 전방 선언 추가 | **모든 함수 정의가 순서대로 전후 동일한지**(문법 트리, 같은 이름이 `#if`/`#else`로 여러 번 나와도 각각 비교). 주석·줄 이음(`\`)을 컴파일러처럼 처리한 뒤, 새로 쓴 줄이 지운 줄을 옮긴 것인지와 지운 줄이 어딘가에 다시 있는지 확인(새 매크로·초기값 변경 거절). C/C++만 지원 |
| 함께 수정되는 파일 | AI가 이유와 함께 적은 후보 파일의 `#include`/`using` 줄만, 파일당 6줄 이하 | 바뀐 줄이 모두 include/using 형식인지(`using A = B;` 별칭·줄 끝 주석·줄 이음 거절), 그 밖의 코드는 컴파일러가 보는 그대로인지 |
| 새 파일 | 선언만 담은 헤더(.h/.hpp) 최대 3개, 20KB 이하 | 함수 정의가 없는지, 내용이 옮겨 온 선언과 포함 가드뿐인지, 기존 파일(대소문자 무시)이나 **기존 `#include`가 가리키는 이름**(예: `SDL.h`)과 겹치지 않는지, 주석이 아닌 실제 `#include`로 쓰이는지 |

전체 편집은 최대 80개이며(파일당 개수 제한은 두지 않음), AI에 제공한 코드 범위 밖의 교체·선택 밖 파일 변경·파일 삭제·이름 변경·빌드 설정 변경은 거절합니다. 새로 들어간 탭·줄바꿈 외 제어 문자(폼 피드 등)와 삼중 문자(`??/`)도 거절합니다. 줄은 분석기·컴파일러와 같이 `\n`으로만 나눕니다.

선언 정리는 '옮기기'만 허용하지만, 옮긴 뒤 순서가 바뀌어 생기는 효과(예: 매크로 정의가 쓰이는 곳보다 뒤로 감)까지 증명하지는 못합니다. 그래서 빌드와 직접 플레이 확인이 꼭 필요합니다. 분석기는 헤더를 단위로 세지 않고 `.c` 파일의 직접 `#include`만 연결로 셉니다. 따라서 헤더끼리 서로 포함하는 연결은 처방 효과 숫자에 드러나지 않을 수 있습니다. 적용 직전에 원본(현재 라운드 기준) 파일의 해시를 다시 확인하고, 사본에는 빌드 캐시·자격 증명·외부 링크를 복사하지 않습니다. 정밀 분석(Clang)으로 분석한 작업은 같은 컴파일 설정의 경로를 사본으로 옮겨(시연 게임은 준비된 설정을 사본에 다시 생성) 수정본도 Clang으로 다시 분석합니다.

**수정본 생성·재분석 완료와 게임 빌드·동작 확인은 서로 다른 상태**입니다. 등록된 OpenTyrian 시연은 현재 라운드 수정본 전체를 원본과 비교해 바뀐 파일과 새 파일을 반영하여 빌드합니다. 같은 OpenTyrian 소스를 새로 가져온 작업도 소스 내용이 같으면 시연 게임으로 인식합니다. 그 밖의 프로젝트는 수정본 ZIP을 내려받아 개발 환경에서 빌드·실행해 확인합니다.

## 엉킴 총량

처음 분석(라운드 0)을 100으로 두고 다섯 절대값(순환 고리에 묶인 파일 수, 파일 사이 연결 수, CC>20 함수 수, Σ max(0, CC−10), 전역 상태 접근 수)의 비율을 평균합니다. 처음 값이 0인 항목은 뺍니다. G-SI는 프로젝트 안의 순위라 전체가 좋아져도 그대로일 수 있으므로, 이 값으로 실제 양의 변화를 봅니다. 같은 프로젝트의 라운드끼리만 비교하며, 분석된 파일 집합이 바뀌면 표시합니다.

| 본인 API 키 | 서비스의 API 키와 사용 가능한 모델 이름 | 키의 계정에 과금. 요청·응답 대역 검사만 수행, 실제 유료 호출 미수행 |
| 다른 AI (주소로 연결) | OpenAI 호환 API 주소, 모델 이름, 필요하면 API 키. 화면에서 OpenAI·Gemini·Claude API·OpenRouter·DeepSeek·Mistral·Groq·Ollama·LM Studio 주소를 고르거나 직접 입력 | 키의 계정에 과금, 이 PC의 Ollama·LM Studio는 무료. ‘모델 목록 불러오기’(GET /models)로 생성 없이 연결 확인. 가짜 서버로 요청 형식·JSON 모드 미지원 재시도·응답 해석을 테스트 |

여러 프로그램이 준비돼 있으면 Claude Code → Codex → Gemini CLI 순서로, 로그인이 확인된 것을 먼저 고릅니다. 공식 로컬 프로그램을 도구 없이 실행해 응답만 받는 방식이며, 웹이 다른 서비스의 로그인 정보를 가져오지 않습니다. 계정 모드에는 환경의 API 키를 넘기지 않습니다. 고른 프로그램이 이 PC에 없으면 화면이 연결 방법을 ‘API 키’로 바꿔 보여 주며, 요청을 보낸 뒤 서버가 다른 서비스로 바꾸지는 않습니다. 설치 확인은 로그인 성공이나 잔여 한도를 뜻하지 않습니다. 주소로 연결할 때 이 PC 밖의 주소는 https만 받습니다(키가 암호화되지 않은 채 전송되지 않도록). API 키는 기록·보고서·브라우저 저장소에 남기지 않고 요청할 때만 사용합니다(서비스·방식·모델·주소 선택만 기억합니다).
