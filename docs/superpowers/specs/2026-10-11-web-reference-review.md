# 웹 프로그램 첫 화면 참고 검토

검토일: 2026-10-11. 목적: 사용자가 소스 입력과 분석 시작을 간편하게 할 수 있도록 첫 화면의 실제 입력 구조를 비교한다. 아래는 공개 첫 화면에 한정한 검토이며 로그인 후 분석 과정이나 각 서비스의 분석 정확도를 검증한 것은 아니다.

## 1. CodeFactor — 저장소 주소로 시작

출처: https://www.codefactor.io/

첫 화면 상태: 입력과 주요 버튼의 관계가 명확하다. 중앙에 저장소 URL 입력과 `Code Review now` 버튼을 배치한다. 아래에 지원 언어와 기존 분석 예시를 제공한다.

![CodeFactor 첫 화면](</C:/Users/dudwl/Desktop/Projects/졸업작품/.cache/web-design-references/01-codefactor.jpg>)

빌려올 요소: 공개 저장소 주소로 시작하는 입력과 분명한 실행 버튼. 우리 첫 화면에는 전체 언어 목록이나 긴 사례 목록을 펼치지 않는다. 배경 그래픽, 브랜드, 서비스의 결과 지표는 복제하지 않는다. 저장소 가져오기 후 분석 대상 폴더와 언어를 확인하는 별도 단계는 우리 분석기의 제약에 맞춰 필요하다.

## 2. VirusTotal — 입력 방법을 탭으로 분리

출처: https://www.virustotal.com/gui/home/upload

첫 화면 상태: FILE·URL·SEARCH 탭으로 입력 방법을 나누고 선택한 탭의 입력만 보여준다. 파일 선택 버튼이 중앙에 있다. 다른 목적의 보안 분석 서비스이며 우리 도구의 코드 품질 분석과 기능이 같다는 뜻은 아니다.

![VirusTotal 첫 화면](</C:/Users/dudwl/Desktop/Projects/졸업작품/.cache/web-design-references/02-virustotal.jpg>)

빌려올 요소: GitHub·ZIP·내 PC 폴더를 탭으로 나눠 세 개의 폼을 동시에 펼치지 않는다. 선택한 입력의 간단한 설명과 한 개의 주요 실행 버튼만 보여준다. 로컬 분석 프로그램에서는 소스를 외부 분석 서비스에 업로드하지 않는다는 사실을 명시한다. URL 탭이라는 이름만 가져와 임의 웹페이지 분석을 지원하는 듯 표현하지 않는다.

## 3. Google 검색 — 시작 화면의 낮은 정보 밀도

출처: https://www.google.com/

첫 화면 상태: 중앙 입력과 실행에 집중하며 주변 기능은 가장자리로 분리한다. 최초 캡처에는 브라우저 설치 안내가 화면을 가렸으므로 이를 닫은 뒤 가림 없는 화면을 다시 캡처했다. 설치 또는 로그인을 수행하지 않았다.

![Google 첫 화면](</C:/Users/dudwl/Desktop/Projects/졸업작품/.cache/web-design-references/03-google-clean.jpg>)

빌려올 요소: 충분한 여백, 짧은 문구, 한눈에 들어오는 입력. 우리 프로그램에 검색·채팅 기능이 없는 만큼 검색창이나 대화창처럼 기능을 오해하게 만드는 표현은 피한다.

## 권장 조합 — 승인 대기

첫 화면은 작은 이름/로고, `게임 소스 코드의 구조와 복잡도를 분석합니다`라는 한 줄 설명, 중앙 입력 카드로 구성한다. 입력 카드는 `GitHub`·`ZIP 파일`·`내 PC 폴더` 탭을 제공하며 기본 탭은 GitHub다. 실제 공개 GitHub 저장소를 가져오는 기능은 아직 구현되지 않았다.

GitHub 모드는 공개 저장소 주소만 받는 것으로 시작한다. 프로그램이 소스 스냅샷을 작업별 로컬 폴더에 내려받고 버전(커밋), 언어, 선택한 하위 폴더를 기록한다. 저장소가 섞인 언어이거나 분석 범위가 모호하면 가져온 뒤 범위 확인을 거쳐 분석한다. 기본 브랜치는 바뀔 수 있으므로 결과 재현을 위해 실제 가져온 커밋을 기록한다.

이는 기존 폴더/ZIP 설계의 범위 확대다. 사용자 승인 후 기존 설계 문서와 구현 계획에 반영해야 하며 아직 서버·업로드·가져오기 코드를 작성하지 않는다. 안전한 다운로드는 GitHub 공식 도메인에 한정하고 HTTPS·크기·시간·압축 해제 제한, 리디렉션 목적지 검사를 둔다. 임의 URL, 사설 네트워크, 비공개 저장소 인증, 하위 모듈/LFS 자동 가져오기, 프로젝트 빌드 스크립트 실행은 첫 버전에서 지원하지 않는다. 내용이 불완전하거나 추가 환경이 필요하면 설명하고 폴더 모드로 안내한다.

고급 설정은 접고, `내 분석 결과`와 `분석 예시`는 작은 보조 메뉴로 제공한다. 준비·실행·완료·부분 분석·실패 상태에서 원인이 필요한 시점에만 안내를 보여준다. 분석 결과와 지원 범위는 기존 분석기 기준을 유지한다.

## 근거와 한계

- 세 화면은 이번 검토에서 직접 캡처한 이미지이며 저장된 이미지까지 확인했다. 사용자 파일을 어느 서비스에도 업로드하거나 분석 요청하지 않았다.
- 첫 화면에서 관찰한 배치에 관한 검토다. 전체 사용자 흐름·로그인 뒤 사용성·모바일·키보드·스크린리더 접근성은 검사하지 않았다.
- [GitHub 소스 아카이브 안내](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)는 브랜치·태그·커밋 단위 다운로드와 재현성 차이를 설명한다. 아카이브에는 전체 Git 이력이 없으므로 이력 기반 기능을 자동 제공한다고 약속하지 않는다.
- [GitHub 저장소 콘텐츠 API](https://docs.github.com/en/rest/repos/contents#download-a-repository-archive-zip)는 공개 저장소 소스 ZIP 다운로드 경로를 제공한다. 이를 사용자가 직접 내려받는 단계를 프로그램으로 옮기는 근거로 사용했다. 우리 도구에서의 호환성·성능은 구현 후 별도 검증이 필요하다.
