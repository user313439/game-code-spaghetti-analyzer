# 점수에서 실제 리팩토링과 검증으로 이어지는 흐름

사용자는 이전 설명의 후보 선정 → 구체적 AI 판단 → 변경안 검토 → 사본 적용·재분석 → 관련 동작 검증 → 보고서 갱신 순서를 승인했다. 같은 폴더에서 수행한다. 유료 API, Git 변경, 학교 제출은 금지한다. 구독 계정 Codex의 실제 제안/변경안 생성과 별도 사본의 수정·게임 검증은 이번 승인 범위다. 이전 실제 작업3aea...와 학교/중간/최종v2 원본을 보존한다.

## 사용자가 보는 결과

선택한 모든 파일에 판단과 이유가 있다. 점수는 검토 순위이며 추천 단위는 실제 함수/코드 구간으로 연결한다. 제안과 실제 변경 범위가 다르면 최신 변경안의 설명을 사용하고 변경/유지/보류 수와 파일 목록은 실제 구조화 데이터에서 계산한다. AI가 새로운 사유를 제공하지 않은 과거 기록에 설명을 만들지 않는다. 과거 기록은 빈 상세 탭/빈 문맥 안내를 숨기고 저장된 최신 설명과 실제 코드 비교만 보여준다.

공동 요약은 선택 전체를 설명하고 파일별 표/탭에서 역할·문제·수정 또는 유지 이유를 확인한다. 실제 변경할 코드와 설명이 일치해야 한다. 긴 해석/제약은 기본 본문에서 반복하지 않고 접힌 검증 정보에 보관한다. 실제 실패와 적용 판단에 필요한 추가 문맥 부족은 숨기지 않는다. 확인 문구와 적용 버튼은 코드 비교 아래 우측의 한 행동 영역으로 묶는다.

## 데이터와 문맥

새 `file_reviews`에 `targets: string[]`를 추가한다. 이는 실제 함수명/선언명이며 AI 프롬프트에 제공한 함수 목록과 코드 근거를 사용한다. UI는 옛 응답에 targets가 없어도 호환한다. 새 refactor 판단에는 구체적 대상이 필요하다. 프롬프트에는 파일별 함수 목록(fqn/name/start/end/cc/loc)을 제한된 분량으로 제공한다. 큰 파일은 복잡도 높은 구간뿐 아니라 전체를 제공 가능한 함수도 포함하며, 변경안 단계는 이전 targets의 해당 함수 문맥을 우선 제공한다. 전체 해시·180KB 원본/360KB 전송·선택 밖/발췌 밖 교체 거절은 유지한다.

사전 검토를 읽는 행동은 AI를 새로 부르지 않는다. 사용자가 변경안 준비를 누르면 현재 선택/원본/연결에 맞는 사전 검토를 바탕으로 preview를 만들 수 있다. 부분 선택의 prior는 해당 파일 리뷰만 포함하며 다른 파일에 대한 공동 설명을 그대로 가져오지 않는다. 기존 main preview를 자동 덮어쓰지 않고 명시적인 다음 행동에서만 새 상태로 전환한다.

## 검증과 보고서

별도 OpenTyrian 입력과 시연 폴더를 사용하여 기존 job/시연 기록을 보존한다. 프로그램의 실제 Codex 경로로 제안과 변경안을 생성한다. 선택 파일 모두의 판단과 preview의 실제 변경을 읽고 검토한 뒤 별도 수정본에 적용한다. 전후 원시 지표/함수/코드 차이, 원본 보존, 원본·수정본 빌드와 관련 계산/동작을 확인한다. 직접 게임 조작은 사용 가능한 컴퓨터 도구로 수행하며 도구 제한은 확인 가능한 범위와 분리한다. 빌드나 과거 검사 결과를 새 수정본 플레이 성공으로 대체하지 않는다.

실패나 어색한 문구를 발견하면 고치고 동일 흐름을 다시 확인한다. 독립 검토로 사양 일치와 코드 품질을 점검한다. 학교 양식과 중간보고서 스타일을 유지해 최종보고서v3를 별도로 작성하고 실제 새 결과에 맞춘 요약/목표/AI흐름/사례/결론을 갱신한다. 원본 v2와 고정 실험/DOOM3 부분 분석/과거 AI는 보존·구분한다. v3 전체 페이지 이미지를 검수하고 검토용 PDF를 준비한다.
