# 로컬 분석 웹 프로그램 설계

작성일: 2026-10-11. 상태: 사용자 승인 후 구현 중. 아래 승인 변경 사항이 초기안과 충돌하면 우선한다.

## 최종 승인 변경 사항

사용자가 공개 GitHub 주소 가져오기와 간결한 입력 구성을 승인했다. 첫 화면은 **GitHub 주소 / 내 파일** 두 탭이다. 내 파일에는 ZIP 선택과 폴더 선택 버튼, 파일/폴더 끌어놓기를 제공한다. 브라우저 폴더 선택은 상대 경로 구조를 유지해 로컬 서버에 복사한다. 원본 폴더는 수정하지 않는다. 끌어놓기 호환성이 부족하면 폴더 선택 버튼으로 안내한다. 폴더 경로 입력은 Clang 환경을 그대로 써야 하는 고급 설정의 선택 항목으로만 남긴다.

GitHub는 공개 저장소 HTTPS 주소만 받는다. 기본 브랜치의 실제 커밋을 먼저 확인하고 그 커밋의 소스 ZIP을 가져와 기록한다. 다운로드와 압축 해제는 용량·시간 제한 및 공식 도메인 리디렉션 검사를 적용한다. 비공개 인증, 임의 웹 URL, Git 하위 모듈/LFS 자동 다운로드, 빌드 스크립트 실행은 지원하지 않는다. 가져오기 후 혼합 언어는 사용자가 분석 언어와 하위 폴더를 확인한다.

승인된 동작 흐름은 입력 → 소스 가져오기/업로드 → 대상 확인 → 분석 시작 → 결과 보기다. 대상 확인 화면은 폴더·언어를 정하는 작은 카드이며 복잡한 관리 화면으로 만들지 않는다. 참고 서비스의 브랜드·그림·문구를 복제하지 않는다.

## 목표와 승인된 방향

사용자는 복잡한 관리 대시보드보다 필요한 기능만 보이는 실용적인 화면을 원한다. 본인 PC에서 실행한 웹 프로그램에 게임 소스를 입력하고 분석 버튼을 누르면, 실제 분석을 거쳐 기존 HTML 대시보드로 결과를 확인한다. 기존 분석 엔진과 검증 사례는 유지한다. 인터넷 공개 서비스, 계정, 자동 코드 수정, 유료 AI 호출은 이번 범위가 아니다.

직전 대화에서 로컬 웹 프로그램과 폴더 지정·ZIP 업로드 방향은 승인되었다. 아래 세부 설계를 확인받은 뒤 구현한다. 문서 정리·GitHub 반영은 보류하며 이 설계 문서도 아직 커밋하지 않는다.

## 접근 방법 비교

1. **권장: 작은 Python 웹 서버 + HTML/CSS/JavaScript.** 기존 CLI를 별도 프로세스로 실행한다. 화면과 분석을 분리하면서 별도 프런트엔드 빌드 도구 없이 구현할 수 있다.
2. **명령어 실행 도우미만 추가.** 작업량은 작지만 사용자에게 입력·진행·결과가 이어지는 웹 프로그램을 제공하지 못한다.
3. **별도 SPA 또는 공개 웹 서비스.** 확장 여지는 있지만 배포·계정·원격 소스 보안 등 현재 요청과 무관한 복잡성이 늘어난다. 이번에는 선택하지 않는다.

서버는 FastAPI와 Uvicorn을 선택형 `web` 의존성으로 추가한다. 파일 업로드 처리는 공식 `UploadFile` 방식과 `python-multipart`를 사용한다. 기존 CLI만 쓰는 사용자에게 웹 의존성을 강제하지 않는다. 기본 분석은 기존 tree-sitter/Roslyn을, 선택형 분석은 기존 Clang을 사용한다.

참고: [FastAPI 파일 업로드](https://fastapi.tiangolo.com/tutorial/request-files/), [서버 실행](https://fastapi.tiangolo.com/deployment/manually/), [Python ZIP 처리 및 위험](https://docs.python.org/3/library/zipfile.html).

## 첫 화면과 사용 흐름

- 기본 화면은 중앙의 간단한 소개, 소스 입력 카드, `분석 시작` 버튼, 접힌 `고급 설정`으로 구성한다. 기술 수치·진단·긴 안내를 처음부터 나열하지 않는다.
- 입력은 `ZIP 첨부`와 `내 PC 폴더` 두 방식으로 전환한다. ZIP은 파일 선택과 끌어놓기를 지원한다. 첫 버전의 로컬 폴더 지정은 탐색기에서 복사한 폴더 경로 입력이다. 브라우저의 파일 선택창이 전체 로컬 경로를 알려준다고 가정하지 않는다.
- 입력 카드에 `게임 실행 파일이 아니라 소스 코드를 선택해 주세요`라는 짧은 설명을 둔다.
- 분석 이름은 입력 이름에서 기본값을 제공하며 변경할 수 있다. 언어 자동 선택을 기본으로 하되 혼합 언어 프로젝트는 언어와 하위 폴더를 선택하도록 안내한다. ZIP 내부 하위 폴더는 서버에서 안전하게 확인한 상대 경로만 선택한다.
- `고급 설정`에는 언어, 기본/컴파일 설정 기반 분석 선택을 둔다. Clang을 선택한 때만 컴파일 데이터베이스와 libclang 경로 입력을 표시한다. 임의 명령어 또는 자유 형식 컴파일 인자는 받지 않는다.
- 분석 시작 후 같은 화면에서 현재 단계와 경과 시간을 표시한다. `소스 확인 → 코드 분석 → 지표 계산 → 결과 생성`처럼 실제 관측 가능한 상태만 보여준다. 알 수 없는 처리량을 숫자 퍼센트로 꾸미지 않는다.
- 종료 후 분석 상태와 `결과 보기`를 제공한다. 완성된 기존 대시보드로 연결하며 결과를 다시 만들거나 임의 수치로 요약하지 않는다.
- 보조 메뉴는 `내 분석 결과`와 `분석 예시` 두 가지다. 기존 결과 모음은 분석 예시로 보존하며 새 분석과 구분한다. 기존 페이지를 대대적으로 수정하지 않는다.
- 실패 안내는 사용자 행동 중심의 짧은 문장으로 표시하고, 원본 로그는 필요할 때 펼친다. 긴 로그·파일 경로는 메인 화면에 상시 노출하지 않는다.

## 구조와 실행

정식 분석 실행 파일은 기존 `game_si/cli.py`의 `analyze`다. 웹 서버는 `sys.executable -m game_si analyze ...`를 인자 배열로 실행하고 `shell=False`를 유지한다. 웹 요청에서 `cli.main()`을 직접 호출하지 않는다. CLI의 표준 출력 설정과 분석 라이브러리 상태가 서버 요청에 섞이는 것을 피한다.

웹 실행 진입점은 `python -m game_si.web`로 별도 추가한다. 기본은 `127.0.0.1` 전용이며 외부 주소 바인딩은 제공하지 않는다. 포트가 이미 사용 중이면 이해하기 쉬운 안내를 한다. 초보자용 실행 안내를 제공하되 패키지 설치나 환경 변수 변경을 자동으로 수행하지 않는다.

역할별 파일 후보:

- `game_si/web/__main__.py`: 로컬 서버 실행과 종료.
- `game_si/web/app.py`: 웹 API, 입력 검사, 결과 제공.
- `game_si/web/jobs.py`: 작업 상태·분석 프로세스·실행 제한·기록.
- `game_si/web/uploads.py`: ZIP 검증과 제한된 해제.
- `game_si/web/static/`: 첫 화면과 정적 자원. 기존 대시보드 CSS는 변경하지 않는다.
- `tests/test_web_*.py`: 입력·안전성·실행·HTTP·화면 회귀 검사.
- `pyproject.toml`: 선택형 웹 의존성 및 정적 자원 패키징.
- `README.md`와 웹 사용 안내: 실행과 입력·지원 범위를 설명하는 작은 추가.
- `.gitignore`: 사용자 업로드·웹 작업 결과의 커밋 방지 규칙만 추가.

새 작업은 UUID로 식별하며 `.cache/web/jobs/<id>/`에 입력과 출력을 분리한다. 기존 `reports/`에는 새 결과를 쓰지 않는다. 작업 기록은 서버 재실행 후에도 확인 가능하며, 중단된 작업을 완료로 표시하지 않는다. 입력 업로드와 결과는 로컬 디스크에 보관된다는 사실을 안내한다. 첫 버전에는 자동 삭제나 이력 삭제 기능을 넣지 않는다.

한 번에 한 작업만 실행한다. 중복 실행 요청에는 현재 작업을 안내하며 무제한 대기열을 만들지 않는다. 상태는 준비/실행/완료/부분 분석/실패/중단을 구분한다. CLI 종료 코드 0과 3은 각각 완료·부분 분석 후보이며, 이번 작업 폴더의 결과와 상태 JSON까지 확인해야 결과 링크를 활성화한다. 다른 종료 코드는 실패다.

총 실행 제한은 기본 30분이며 Clang 파일별 제한은 기존 기본값 60초를 유지한다. 시간 초과·서버 종료에서는 이 작업의 추적된 분석 프로세스와 자식 프로세스를 종료하고 중단으로 기록한다. 무관한 프로세스는 종료하지 않는다. 첫 버전에서는 별도 취소 버튼보다 종료·시간 초과의 안전한 처리를 우선한다.

## 지원 범위와 안전성

- 입력은 신뢰할 수 있는 C#/C/C++ 소스다. EXE·게임 설치 파일·미지원 언어는 분석 대상이 아니다. 헤더는 컴파일 문맥에 사용할 수 있지만 별도 구현 파일 분석 범위와 혼동하지 않는다.
- ZIP은 압축 파일 최대 100 MiB, 해제 총량 최대 1 GiB, 파일 최대 20,000개로 제한한다. 실제 수신·해제 바이트도 검사하고 초과하면 중단한다. 손상·암호화·심볼릭 링크·중복 대상·절대 경로·상위 경로 이동·Windows 드라이브/특수 경로와 장치 이름을 거부한다. 모든 해제 대상이 해당 작업 입력 폴더 안인지 확인한다.
- 업로드 소스의 실행 파일·빌드 스크립트를 실행하거나 의존성을 자동 설치하지 않는다. ZIP 안의 프로그램을 실행할 수 있는 파일 서버를 만들지 않는다. 분석기 자체가 보안 샌드박스라는 표현도 하지 않는다.
- 로컬 폴더는 읽기 전용 분석 대상이다. 선택한 소스 코드와 기존 분석 결과를 수정하지 않는다. 사용자 입력 경로를 공개 정적 서버 루트로 마운트하지 않는다.
- Clang 설정에는 현재 PC에서 존재하는 헤더·매크로·라이브러리가 필요하다. 업로드된 소스와 컴파일 데이터베이스의 절대 경로는 자동으로 재작성하지 않는다. 맞지 않으면 로컬 폴더 모드와 설정 확인을 안내한다.
- 서버는 Host와 Origin을 검사하고 쓰기 요청에 세션별 토큰을 요구한다. 외부 사이트가 로컬 폴더 분석이나 파일 업로드를 몰래 요청하는 경로를 막는다. CORS를 광범위하게 허용하지 않는다.
- 결과 URL은 승인된 작업 ID와 결과 파일만 제공한다. 경로 탈출, 사용자 소스·환경 파일·임의 파일 공개를 차단한다. 예시는 지정한 보고서 디렉터리의 허용된 HTML/결과 링크만 제공한다.
- 기본 작업에서 AI API를 호출하지 않는다. 과거 예시에 AI 제안이 있더라도 새 분석에서 생성한 제안으로 표시하지 않는다.

## 완료 기준과 검증 순서

- [ ] 기존 분석기·설정·화면·검증 자료 확인.
- [ ] 사용자 요구를 설계로 정리하고 세부 설계 승인 받기.
- [ ] 승인 후 구현 계획 작성 및 테스트 우선 구현.
- [ ] 폴더와 ZIP에서 지원 소스를 실제 분석하여 새 작업의 HTML 결과 확인.
- [ ] 부분 분석은 결과를 유지하고, 실패는 성공으로 표시하지 않기.
- [ ] 잘못된 경로·손상 ZIP·경로 탈출·용량 초과·미지원 입력·중복 실행·서버 중단 검사.
- [ ] 정상·부분·실패 작업과 재시작 기록을 HTTP 통합 테스트로 확인.
- [ ] 실제 CLI 실행과 웹 실행의 동일 입력 지표가 같은지 비교.
- [ ] 기존 전체 테스트 재실행, 기존 보고서 수치·파일 보존 확인.
- [ ] 패키지에 웹 정적 자원 포함 여부와 선택형 의존성 분리 확인.
- [ ] 가능한 브라우저 도구로 동작·반응형 화면 확인. 도구가 허용하지 않는 경우 우회하지 않고 HTTP/자동 테스트 범위와 사용자 확인 필요 부분을 명시.
- [ ] 사용자에게 실행 방법과 확인 링크를 제공하고 UI 피드백을 수용.

## 설계 자체 검토

폴더 지정과 브라우저 업로드의 차이, 전체 소스 범위와 분석 정확도의 차이, Clang의 외부 설정 조건을 분리했다. 완료·부분 분석·실패는 기존 CLI/상태 JSON에서 도출하며 가짜 진행률이나 과거 결과 재사용을 허용하지 않는다. 공개 서비스와 유료 AI는 범위 밖이다. 구현 시 의존성과 구체적인 API는 계획에서 확정하되 사용자 경험과 안전 요구를 축소하지 않는다.
