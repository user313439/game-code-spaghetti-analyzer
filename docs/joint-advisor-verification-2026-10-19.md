# 공동 검토·파일 탭·상위 5개 사전 검토 검증

2026-10-19. 기존 폴더에서 사용자가 승인한 UI/어드바이저 보완을 진행했다. 실제 AI 요청, 현재 게임 변경안 적용, 유료 API, 커밋·브랜치·push·학교 제출은 하지 않았다. 학교 원본과 최종보고서 v2도 보존했다.

## 구현 결과

- 공동 요약과 파일별 상세를 함께 제공한다. 새 응답은 선택 파일마다 역할·확인 내용·이유·변경 방향·기대 효과·영향·근거·확인할 동작을 갖고, 변경/유지/추가 문맥 필요를 구분한다. 누락·중복·선택 밖 경로를 거절한다. 변경안의 실제 수정 파일과 변경 판단도 일치해야 한다.
- 제안·코드 비교·결과에 선택 파일 전체 탭을 제공한다. 비교는 원본/수정본 좌우 배치이며 실제 수정하지 않는 파일도 ‘변경 없음’으로 표시한다. 결과는 적용한 사실·당시 AI 방향·측정 지표를 구분한다. 새 재분석 비교에는 유지한 선택 파일도 포함한다.
- ‘상위 5개 미리 검토’는 명시적으로 누를 때만 요청한다. 후보 클릭은 저장 결과의 해당 파일 탭을 활성화하며 추가 AI 요청을 만들지 않는다. 기존 미적용 변경안과 별도 파일에 저장한다. 원본 해시·후보/지표·연결·모델·검토 형식이 같으면 재사용하고, 다른 연결로 만든 기록은 당시 연결을 표시한다.
- 원본 파일당 180,000바이트, 전송 JSON 360,000바이트, 정확한 교체 최대 12개 제한을 적용한다. 큰 묶음은 앞부분·복잡도가 높은 함수·끝부분을 제공하고 실제 범위와 전체 파일 해시를 기록한다. 발췌 밖 교체는 승인 가능한 변경안이 되지 못하며 Windows 줄바꿈을 지원한다.
- 진행 카드는 작업·실제 단계·막대·경과 시간으로 정리했다. 게임 카드는 이름·짧은 소개·우측 하단 실행 버튼을 기본으로 하고 준비 중 진행/실제 오류만 추가한다. 코드 제안의 다음 행동 버튼도 우측 하단이다.
- 표 자체를 native table로 복원하고 가로 스크롤은 바깥 래퍼에 맡긴다. 저장 보고서를 수정하지 않고 웹 응답에만 배치 보정을 적용한다.

## 자동·독립 검증

최종 전체 검사 **473개 통과**, `.NET 8`과 지정된 테스트용 libclang 환경으로 수행했다. 최종 결과는 `docs/_verification/2026-10-19-joint-advisor/full-tests.txt`에 저장했다. 관련 JS 세 파일의 구문 검사와 `git diff --check`도 수행했다.

중점 검사는 별도 사전 검토/기존 preview 보존, 캐시 재사용·소스/지표/모델 변경 무효화, 파일별 전체 응답 범위, 선택 밖/발췌 밖 교체 거절, CRLF 호환, 모든 선택 파일 해시 확인, 유지 파일 전후 비교, 진행 중 기록 삭제 차단이다. 독립 검토에서 찾은 범위·줄바꿈·삭제 보호 문제를 보완하고 회귀 검사로 확인했다.

## 실제 입력과 기록 보존

실제 작업 `3aea3d5698314a28a8c6b38a0ff9f2f8`은 여전히 **5개 검토·2개 미적용 변경안**이다. 현재 변경 예정 파일은 `mainint.c`, `opentyr.c`이며 적용 결과나 게임 검증 성공으로 표현하지 않는다. 기존 `assistant.json` SHA256은 다음 값과 동일하다.

`578daf085aaeb4c8196830c5e1dd822eed8a6c71adea6238739f79ec143a890d`

실제 상위 5개 원문 합계 421,142바이트를 읽기 전용으로 준비했을 때 전송 JSON은 **133,798바이트**였다. 전체 소스 제공이 아닌 발췌이며 어떤 파일/줄이 포함되는지 `preservation-and-context.json`에 기록했다. 이 프롬프트를 AI에 보내지는 않았다.

## 브라우저 확인

실제 작업은 읽기 전용으로 기존 제안·변경안 탭을 확인했다. 별도 캐시의 검사 전용 C 소스와 명시적인 대체 AI 응답으로 사전 검토→5개 선택→제안→2개 변경/3개 유지→사본 생성→재분석→파일별 결과 흐름을 검수했다. 게임 준비·실행 버튼도 대체 준비/실행 응답으로만 검사했다. 실제 게임 프로세스는 실행하지 않았다.

- 블루/화이트: 표·머리글·본문·래퍼 폭이 모두 1,201px이었다.
- 다크 embedded: 표·머리글·본문·래퍼 폭이 모두 1,216px이었다.
- 실제 iframe의 문서 높이와 할당 높이가 일치했고 필터 변경 후에도 전체 페이지 스크롤을 유지했다.
- 390px iframe 검수에서 내부 문서 clientWidth/scrollWidth가 모두 375px로 가로 넘침이 없었다. 파일 탭 전환과 상세 문단도 확인했다.

화면 증거는 `docs/_verification/2026-10-19-joint-advisor/screens/`에 있다. `provider-trace.json`과 `synthetic-launch.json`은 검사 자료이며 실제 리팩토링 실험 결과가 아니다. 새 응답 형식의 실제 서비스 응답과 현재 실제 변경안 적용·빌드·플레이는 이번 검증에 포함하지 않았다.
