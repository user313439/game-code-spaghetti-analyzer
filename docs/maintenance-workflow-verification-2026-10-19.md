# 유지보수 흐름과 실제 OpenTyrian 검증

2026-10-19. 같은 작업 폴더에서 승인된 기능을 보완하고 별도 실제 사례를 만들었다. 기존 미커밋 변경·학교 원본·중간보고서·최종보고서 v2·이전 AI 및 시연 기록을 보존했다. 브랜치·worktree·커밋·push·유료 API·학교 제출은 하지 않았다.

## 구현과 검토

- 모든 선택 파일의 판단·구체 함수·이유를 보존한다. 최신 변경안의 설명으로 공동 요약·파일별 판단·코드 차이·적용 결과를 통일한다.
- 과거 응답에 없는 설명을 생성하지 않는다. 빈 상세와 반복된 한계 문구는 기본 화면에서 제거하고 원문·검증 정보는 접어서 보존한다.
- 사전 검토의 선택 부분집합으로 제안 요청을 반복하지 않고 변경안을 준비한다. 연결·모델·선택·소스 해시가 맞아야 재사용한다.
- 새 targets는 실제 함수 목록과 대조한다. 실제 수정한 기존 함수가 선언한 대상과 일치해야 한다. 새 C/C++ helper는 전후 AST로 검출해 static·설명 이름·변경 대상의 실제 호출을 검사한다.
- 수정할 코드가 없는 판단은 이유를 저장한 정상 완료이며 승인 데이터를 만들지 않는다.
- 승인 전과 사본 복사 후 선택 파일 전체 해시를 확인한다. 유지 판단 파일이 복사 중 바뀌는 경합도 거절한다.
- 승인 문구·버튼을 우측 인접 그룹으로 묶었다. 코드·전후 지표는 파일 탭으로 비교한다. 결과 요약은 실제 CC 감소와 SI 감소·유지·상승을 직접 설명한다.
- 게임 카드는 이름·짧은 설명·우측 실행 버튼 중심으로 유지하고 현재 검증과 조작법은 접었다. 진행 표시는 실제 단계·막대·경과 시간만 사용한다.

독립 리뷰에서 함수 대상 불일치, 무변경 판단 유실, 복사 경합, helper diff 정렬 우회를 발견해 회귀 검사와 함께 보완했다. 최종 재검토에서 승인 범위의 잔여 중요 문제는 발견하지 못했다.
