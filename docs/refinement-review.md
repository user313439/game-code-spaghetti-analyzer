# 최종 보완 및 재검수 (2026-10-04)

후속 기록(2026-10-05): [오류 안내 및 화면 보완 검수](safety-ui-review.md). 아래는 10월 4일 검수 기록이다. 후속 보완에서는 점수·메트릭은 유지하면서 정상/부분/실패를 표시했고, C/C++ 파서 복구 범위를 새로 확인했다. 과거의 235개 검사를 최신 수정 소스에 대한 검사라고 간주하지 않는다.

## 결론부터

졸업작품의 기존 기능을 유지하면서 실제 분석 오류를 수정하고, 같은 입력의 실험을 다시 했다. 현재는 **최종보고서에 사용할 검증된 프로젝트 후보**다. 학교의 합격·점수나 상용 도구 수준의 무결성을 보증하는 뜻은 아니다. Word 최종보고서·포스터·학교 제출·GitHub 공개는 아직 별도 단계다.

가장 적절한 작품 설명은 **게임 코드의 구조를 여러 관점에서 보여 주고 소스 검토 후보를 제시하는 도구**다. “다른 도구보다 결함을 더 정확히 찾는다”, “높은 점수는 나쁜 코드다”, “리팩토링 효과를 입증했다”는 주장은 하지 않는다.

## 1. 실제로 보완한 것

| 문제 | 보완 |
|---|---|
| 같은 이름의 메서드 때문에 정확한 호출이 누락되거나 외부 호출이 로컬 메서드로 연결됨 | 정확한 전체 이름과 Roslyn 원형 심볼을 우선 사용. 모호한 후보는 임의 연결하지 않음 |
| 오버로드·제네릭·동명 클래스가 그래프에서 합쳐짐 | 제네릭 원형 보존, 메서드 오버로드·소스 위치별 선언 식별, 파일 귀속 유지 |
| 외부 타입 및 로컬 함수가 동명 로컬 타입/클래스 메서드로 연결됨 | 실패 테스트로 재현한 뒤 연결 차단 |
| 동점 후보 순서·순환 목록·이웃 목록이 실행마다 달라질 수 있음 | 파일 경로 및 이름 기준 정렬 고정 |
| A=안전, E=심각, Health=절대 품질처럼 읽히는 설명 | 내부 상대 순위·동점·보조 구조 요약으로 수정. JSON에 `ranking_info` 추가 |
| 잘못된 가중치가 기본값으로 바뀌거나 예외·부분 결과를 생성함 | 객체·키·숫자·음수·합·표현 범위를 검증하고 분석 시작 전에 오류 안내 |
| 게임 특화 항목이 실제로 도움이 되는지 근거 부족 | 사전 고정 7개 조합의 지표 제거 실험 추가. 유리한 결과만 선택하지 않음 |
| 후보 목록 차이만 있고 실제 소스 설명 부족 | [양방향 소스 사례 검토](case-study-review.md) 추가 |

기본 가중치 `.30/.25/.15/.15/.15`와 `#(값 ≤ x)/N × 100` 공식은 바꾸지 않았다. 중간보고서 승인본도 수정하지 않았다. 테스트 우선 절차로 결함을 먼저 재현하고 실제 C# 추출 통합 검사와 독립 코드 검토를 수행했다.

## 2. 보완 전·후 비교

같은 저장소 SHA, 같은 파일 집합, 같은 과거 bug-fix 집계를 사용했다. 종료일은 **2026-10-03 UTC**로 고정했다. 실행·정리는 한국시간 10월 3~4일에 걸쳐 진행했다. 수치 차이는 원본 게임을 개선한 결과가 아니라 **분석기 오류를 수정한 결과**다.

| 사례 | 파일 수 | 보완 전 G-SI ρ | 보완 후 G-SI ρ | LOC ρ | CC ρ |
|---|---:|---:|---:|---:|---:|
| OpenRA.Game | 226 | 0.6011 | 0.6050 | 0.6988 | 0.5517 |
| OpenRA.Mods.Common | 1,080 | 0.5363 | 0.5353 | 0.6129 | 0.5265 |
| Chocolate Doom | 296 | 0.5851 | 0.5851 | 0.6158 | 0.4676 |
| OpenRCT2 | 544 | 0.4598 | 0.4687 | 0.4062 | 0.3681 |

ρ는 **파일 단위 Spearman 상관**이다. 커밋 메시지 키워드에 따른 과거 bug-fix touch count와의 관련성이고 미래 결함 예측 성능이 아니다. OpenRA.Game의 클래스 단위 ρ는 음수다. 분석 단위를 생략하지 않는다. LOC보다 높지 않은 사례가 있으므로 범용 우월성도 주장하지 않는다.

동명 선언을 보존한 결과 현재 8개 사례 모두 클래스 인덱스 수=그래프 노드 수=분석 클래스 수이며, 메서드 노드 식별자도 중복되지 않는다. 이는 검사한 벤치마크에서의 구조 일치이지 모든 언어 구문을 정확히 해석했다는 보증은 아니다.

Phase B top-30 Jaccard는 Game 0.3636 / Common 0.5000 / Doom 0.3333 / RCT2 0.2500이다. 동점 파일은 경로순으로 자른다. 순위 목록의 차이는 서로 다른 관점을 뜻하며 실제 결함 탐지의 우월성을 뜻하지 않는다.

## 3. 지표 제거 실험: 무엇이 도움 되었나

지표를 하나씩 제거하고 남은 기본 가중치를 재정규화했다. CC+Coupling만 남기는 대조 조합도 포함했다. 같은 클래스 집합에서 표준화·백분위를 계산하고 같은 파일 집합과 bug-fix 값을 비교했다. OpenRA 모듈 평균을 먼저 구한 뒤 **세 원본 프로젝트를 같은 비중**으로 평균했다. 표본 1파일인 Server는 사전 기준으로 제외했다. 조합별 상관이 계산 불가능하면 결측을 남기며 유리하게 표본을 버리지 않는다.

| 사전 지정 조합 | 원본 프로젝트 동일 비중 평균 ρ |
|---|---:|
| 기본 5항목 | 0.5229 |
| CC 제외 | 0.4371 |
| Coupling 제외 | 0.4879 |
| DependencyCycle 제외 | 0.5311 |
| GlobalState 제외 | 0.4942 |
| GameLoopCentrality 제외 | 0.5403 |
| CC+Coupling만 | 0.5262 |

현재 세 프로젝트에서 CC·Coupling·GlobalState를 빼면 평균이 낮아졌지만, 게임 루프 또는 순환을 빼면 오히려 높아졌다. **게임 특화 지표 추가가 항상 더 좋은 통계 성능을 준다고 주장할 수 없다.** 구조 설명과 후보 제시의 가치, bug-fix 상관의 가치는 구분한다. 각 조합의 후보 추가·제외와 겹침은 [ablation.json](../reports/ablation.json)에 포함했다. 동일 표본 탐색이며 유의성·인과관계 검정은 하지 않았다. 결과를 보고 기본 가중치를 다시 선택하지 않았다.

새 프로젝트 단위 LOPO 튜닝 평균은 기본 **0.5229**, hold-out **0.5269**, 차이 **+0.0040**이다. 이 작은 차이를 확실한 개선이나 일반화의 증거로 쓰지 않는다. default를 기본으로 유지한다.

공개된 8개 결과로 지표 제거 실험을 다시 실행하는 명령:

```powershell
python -m game_si ablate --case openra-game=reports/openra-game --case openra-mods-common=reports/openra-mods-common --case openra-mods-cnc=reports/openra-mods-cnc --case openra-mods-d2k=reports/openra-mods-d2k --case openra-server=reports/openra-server --case openra-platforms-default=reports/openra-platforms-default --case chocolate-doom=reports/chocolate-doom --case openrct2=reports/openrct2 --out reports/ablation-reproduction
```

원본 소스부터 재현하려면 고정 SHA를 준비하고 `analyze → validate → compare / score-full / timeseries`를 실행한다. 실험 기준은 위 표와 근거 JSON에 있으며, 로컬 전체 실행 명령은 `py -3.10 -B docs/_verification/run_refinement.py`, 뒤이어 `... run_refinement.py experiments`, `... run_refinement.py timeseries`, `... verify_refinement.py`다. C# 분석 전 `dotnet build csharp-analyzer/csharp-analyzer.csproj`로 Debug 분석기를 빌드한다.

## 4. 검수 범위와 보존

- Python 테스트 **79개** 통과: 실제 Roslyn 추출 통합 검사, 호출·타입·오버로드 회귀, 잘못된 가중치, 상대 순위, 지표 제거 실험, 기존 기능 포함.
- 자동 결과 확인 **235개** 통과: 고정 SHA·저장소 청결, 노드 수·식별자 중복, AST/메트릭/점수 계산 일치, 동일 bug-fix 입력, 조합별 계산·모집단·입력 해시, Full 기간, fold 분리, 32시점과 최신 시점 일치, HTML 내부 JSON·JavaScript 구문 확인.
- .NET 빌드 오류 없음. 재컴파일 시 기존 CS9057 경고(분석기와 컴파일러 버전 차이) 2개가 있었으며 의존성/잠금 파일 변경은 하지 않았다.
- 읽기 전용 독립 검토에서 발견된 중요한 결함을 수정한 뒤 재검사했다. 현재 검토 범위에서 남은 Critical/Important 문제는 발견되지 않았다.
- 최종 반영 파일 83개와 소스 해시를 독립 대조했다. 최신 점수 옆에 남아 있던 과거 AST·메트릭 4개도 보관 후 최신 값으로 교체하여 일치시켰다.
- 브라우저의 실제 클릭·시각 배치는 이번 자동 검수로 확인하지 못했다. 대시보드 코드·내장 데이터·JavaScript 구문과 산출물 존재까지 확인했으며 수동 시연 점검은 남는다.

시계열은 **같은 과거 커밋 8개씩 총 32개를 수정된 분석기로 재실행**했다. 모든 기간에서 단조 악화하거나, 점수 감소가 실제 품질 개선이라는 해석은 하지 않는다. 각 시점의 정규화 집합이 다르다.

근거: [verification-refinement-2026-10-04.json](../reports/verification-refinement-2026-10-04.json). 입력 SHA는 [이전 검증 문서 §1](final-verification.md#1-실험-기준과-보존)의 고정값과 동일하다. 로컬 원본·로그·실행 도구는 `docs/_verification/2026-10-03-refinement/` 및 `docs/_verification/`에 있다. 이 폴더 이름은 작업 시작일이고 실제 실행 시각은 근거 JSON의 UTC 필드에 남긴다.

교체 전 2단계 공개 결과는 `reports/archive/pre-refinement-2026-10-04/`에 보존한다. 더 이전 자료는 `reports/archive/pre-final-2026-10-03/`에 그대로 남긴다. 기존 AI 가이드 20개는 생성 당시 실험 예시이며 새 수치에 대한 검증이 아니다. 최신 대시보드에 자동 혼합하지 않았다. 유료 API·실제 게임 코드 수정·커밋·브랜치·push는 하지 않았다.

## 5. 교수 관점에서 다시 본 판단

비공식 자체 평가로는 문제 설정과 구현·재현 근거가 있는 학부 졸업작품으로 설명할 수 있는 상태다. 보완 전보다 분석 정확성, 실패 사례의 투명성, 연구 질문에 대한 증거가 좋아졌다. 이제 새로운 기능을 크게 늘리기보다 **검증된 범위와 한계를 명확히 설명하는 최종보고서**를 만드는 편이 낫다.

남아 있는 연구 한계:

1. 3개 원본 게임과 과거 커밋 대리 지표만 검증했으며 독립적인 미래 데이터 검증은 없다.
2. 이름 패턴의 게임 루프 탐지와 정적 호출 그래프는 근사다. 외부 DLL·virtual·delegate·event·partial 타입의 완전 해석은 범위 밖이다.
3. GlobalState는 static 메서드와 이름 기반 싱글톤 접근도 포함하는 대리 지표다. C# unique 접근과 C/C++ 접근 횟수는 같은 단위가 아니다. 중첩 타입의 부모 계상 가능성도 있다.
4. 큰 기초 구조체나 메뉴 상태 머신이 상위에 올라와도 반드시 잘못 설계된 것은 아니다. 원시 수치와 소스 확인이 필요하다.
5. 실제 사용자 설문·리팩토링 적용 전후 효과·AI 제안의 정확성은 이번 검증으로 입증하지 않았다.

보고서에서 이 한계들을 공개하면 작품의 결격 사유를 감추는 것이 아니라 **검증 범위를 정확히 설명하는 것**이다. 대규모 분석기 재설계는 후속 연구로 남기고, 최종보고서 → 수동 시연 점검 → 한 페이지 발표 포스터 순서로 진행하는 것을 권장한다.
