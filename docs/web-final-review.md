# 로컬 웹 최종 검수 및 제출 전 상태

검수일: 2026-10-13. 이번 범위는 **기본 디자인 확정 → 실제 사용 검수 → 문서 정리**다. Git 커밋·push, 정식 릴리스, Word 최종보고서, 포스터, 영상 녹화와 학교 제출은 수행하지 않았다.

후속 기록(2026-10-15): 사용자가 직접 체험을 필수 차단 조건으로 두지 않고 커밋·push 정리를 요청했다. 전체 425개 검사를 다시 통과했고, 공개 후보·기존 미전송 이력의 키 패턴 검사와 보고서 보존 확인을 수행했다. [Git 반영 전 검수 근거](../reports/verification-publication-2026-10-15.json)를 별도로 남긴다. 아래는 10월 13일 당시 기록이며, 원격 반영 완료는 실제 push 결과와 원격 커밋으로 확인한다. Word 최종보고서·포스터·영상은 여전히 다음 단계다.

## 1. 현재 작품의 범위

게임의 C#/C/C++ **소스 코드**를 가져와 복잡도·결합도·순환 의존성·전역 상태·게임 루프 연결 지표로 검토 우선순위를 보여주는 로컬 정적 분석 도구다. 공개 GitHub 저장소, ZIP, 소스 폴더를 입력하고 실제 새 분석을 실행할 수 있다. 결과는 표·그래프·원시 지표로 확인하며, 기록은 정렬·삭제·복원이 가능하다.

기본 디자인은 사용자 선택에 따라 **라이트 블루**로 확정했다. 기본 주소부터 예시·새 결과·기록까지 같은 색상을 사용한다. 다크/화이트 비교 옵션은 유지한다. 테마는 HTTP 응답에만 적용해 고정 실험의 HTML/JSON·분석 시각·점수를 변경하지 않는다. 저장된 HTML을 직접 열면 원본 디자인이다.

웹은 새 AI 안내 생성이나 자동 코드 수정을 제공하지 않는다. CLI의 선택형 `advise`와 과거 AI 생성 예시는 별도다. 기본 웹 분석에는 유료 AI 호출이 필요하지 않다. 분석 완료 100%는 **선택한 범위의 처리 상태**이며 정확도·버그 탐지율·전체 게임 이해율이 아니다.

## 2. 오늘 새로 실행한 검수

실제 브라우저에서 입력·버튼·파일 선택을 조작했고, 결과 HTML과 작업 메타데이터를 함께 확인했다. 단순히 이전 예시를 열어 새 분석처럼 설명하지 않았다.

| 입력 방식 | 실제 입력과 범위 | 결과 | 분석 실행 시간 |
|---|---|---|---:|
| 공개 GitHub 주소 | OpenRA/OpenRA, 전체 폴더에서 C# 선택 | 1,517파일, 3,287클래스, 11,674메서드, 순환 8묶음. 완료·실패 0·구문 복구 0 | 28.338초 |

시간은 저장된 `finished_at - started_at`이며 가져오기·사용자 선택 시간은 제외한다. 이 PC의 관측값으로 성능 보장이 아니다. ZIP/폴더의 단일 파일은 입력 연습용이지 여러 파일의 상대 순위를 입증하는 사례가 아니다.

OpenRA 기본 브랜치 `bleed`의 입력 커밋은 `e180e3225f3930272dd451917467631618f8976f`다. 선택 C# 범위에는 엔진·모듈·도구·테스트가 포함된다. C 1파일·자산·외부 DLL의 전체 해석이나 게임 빌드·실행을 검증한 것은 아니다. 웹 옵션의 `backend`는 C/C++ 선택 항목이며, C# 실제 추출은 기존 Roslyn 분석기를 사용한다.

## 3. 상호작용과 보완

- 저장소 주소의 Enter는 소스 가져오기만 실행하고, 범위·언어 확인 후 분석 버튼을 누르는 흐름 확인.
- `/tree/bleed`가 붙은 미지원 GitHub 주소는 안내 후 가져오기를 시작하지 않음.
- OpenRA 결과에서 `Server` 검색은 54개 후보 중 30개 표시, E 필터는 18개 중 18개 표시. 그래프 `Game` 검색은 7노드 강조. 확대·리셋 및 실제 노드 정보 표시 확인.
- 순환 목록을 펼쳐 실제 멤버를 확인하고 대시보드 도움말 펼침/접힘 동작도 확인.
- 기록의 이름순·소스 용량순·최신순 동작 확인. **이번에 만든 ZIP 기록 하나만** 삭제하고 되돌림. 삭제 때 결과 웹 접근은 404, 복원 후 200. 기존 6개 사용자 기록은 유지.
- 표의 정렬 화살표가 설명창과 같은 `::after`를 사용해 설명 대신 화살표가 보이는 현상을 실제 화면에서 재현. 생성기의 화살표를 `::before`로 분리하고 웹 스타일에도 원본 파일을 덮어쓰지 않는 보완 적용.
- 빈 검색 결과의 표에 설명 공간을 확보. 실제 CC 헤더 클릭 후 hover 상태에서 본문 전체 표시, 표 안 세로 잘림·불필요한 세로 스크롤 없음 확인. 좁은 화면에서도 문서 폭=뷰포트 폭 785px, 표 높이=스크롤 높이 160px 확인. 임시 뷰포트 설정은 해제.

이는 선택한 화면·상호작용 검수다. 모든 파일·모든 설명·모든 브라우저 상태의 무결성을 보증하지 않는다. 탐색기에서 끌어놓는 실제 드래그 입력과 사용자 직접 체험은 별도로 남는다. 드래그의 경로·제외·용량·연속 배치 처리는 자동 검사 범위다.

## 4. 자동 검사와 보존

전체 `py -3.10 -m pytest tests -q --tb=short`: **425 passed, 실패 0, 건너뜀 0, 72.00초**. C# native 검사용 .NET PATH와 호환 libclang을 설정한 조건이다. JS 문법 검사도 통과했다. 실패 테스트를 먼저 확인한 후 기본 테마·링크·화살표 설명 충돌을 수정했다.

기존 보고서 226개와 `reports/index.html`은 이전 보존 기준 해시와 일치했다. 점수 산식·기본 가중치·고정 실험의 수치·승인된 중간보고서를 변경하지 않았다. 문서의 과거 실험 수치는 당시 조건의 기록으로 유지하고 최신 웹 검수와 구분했다.

읽기 전용 독립 코드·문서 검토에서 Critical/Important 문제는 발견되지 않았다. 실제 원본 보존을 더 직접 검사하자는 경미한 테스트 제안은 반영해, 고정 예시 파일의 바이트와 다크 원본 응답을 비교하도록 강화했다. 이 판정은 승인 범위에 대한 것이며 Git 공개·학교 제출 준비 전체의 완료 판정은 아니다.
