Game Spaghetti Index (G-SI)는 분석한 구현 파일 집합 내부의 상대적인 검토 우선순위입니다. 절대 품질·결함 확률이나 프로젝트 간 우열을 뜻하지 않습니다.

동점은 상단 백분위로 계산합니다. 모두 동점이면 100/E여도 심각한 결함의 증거가 아니며, 순위로 후보를 구분할 수 없습니다. 원시 지표와 실제 소스를 함께 확인하세요.

분석 범위와 한계
  • 분석 단위는 구현 파일입니다. 파일 간 의존성은 선택한 구현 파일에서 연결한 심볼을 이용한 근사이며 정확한 클래스 그래프가 아닙니다.
  • 원시 CC와 파일 간 결합도·순환·전역 상태·게임 루프 지표를 함께 확인하세요. G-SI는 분석 집합 내부의 상대 검토 순위이며 절대 품질이나 결함 확률이 아닙니다.
  • compile_commands.json에서 파일별 첫 등록 항목 하나의 설정만 선택합니다. 다른 설정·플랫폼·전처리 분기와 미등록 파일은 분석 범위 밖입니다.
  • 헤더는 컴파일 문맥에 사용하지만 헤더 안의 함수 본문을 별도 분석 단위로 추출하지 않습니다. 헤더에서 발생한 진단은 원래 구현 파일별로 집계합니다.
  • 직접 호출은 컴파일 시점 심볼로 연결합니다. 가상 호출의 동적 대상·함수 포인터·이벤트·런타임 상태와 이름 패턴 밖의 게임 루프를 완전히 해석하지 않습니다.
  • CC는 range-for와 중첩 람다 본문을 제외하고 default 분기를 포함합니다. 매크로 생성 함수의 원본 스니펫은 제공하지 않습니다.
  • 호환 libclang으로 분석한 결과이며 원본 빌드 성공을 뜻하지 않습니다. 분석 완료도 전체 코드의 정확한 해석을 보증하지 않습니다.

전체 설정과 진단은 원본 분석 데이터에 보존되어 있습니다.

구조 요약 (보조 Health)

검증되지 않은 보조 구조 요약입니다. 상대 순위 기반 항목을 포함하므로 절대 코드 품질이나 프로젝트 간 우열을 판정하지 않습니다.

다음 네 가지 신호를 가중 평균합니다.

  • 평균 G-SI (45%) — 프로젝트 안 모든 구현 파일의 G-SI 점수를 단순 평균. 가장 큰 비중.
  • 상대 D+E 비율 (25%) — G-SI 60 이상인 구현 파일 비율. 결함 비율이 아닙니다.
  • 순환 의존성 수 (15%) — A→B→C→A 처럼 서로 참조해서 빙빙 도는 묶음의 개수. 로그 스케일 적용(0 → 0점, 1 → 30점, 5 → 70점, 20 이상 → 100점).
  • 평균 결합도 (15%) — 구현 파일 한 개당 평균적으로 몇 개의 다른 구현 파일와 연결되는지(fan-in+fan-out 평균). 평균 10 이상이면 100점으로 saturate.

A~E는 수치 구간만 표시합니다. 평균 G-SI와 D/E 비율은 백분위 공식과 동점에 영향을 받으므로, 이 수치를 전체 품질의 증거로 발표하지 마세요.

Cycle Explorer (Strongly Connected Components)

A → B → C → A 처럼 서로 참조해서 빙빙 도는 구현 파일 묶음(Strongly Connected Component, SCC)을 모은 섹션입니다.

일반적으로 의존성은 한 방향으로 흘러야 합니다(예: UI → 로직 → 데이터). 그런데 두 구현 파일가 서로를 참조하기 시작하면, 한쪽을 수정할 때 반드시 다른 쪽도 함께 신경 써야 합니다. 이런 묶음이 3개, 4개로 커지면 영향 범위 추적이 사실상 불가능에 가까워집니다. 그래서 SCC는 리팩토링 1순위 후보입니다.

본 섹션의 카운트 카드 숫자가 곧 프로젝트 안의 모든 SCC 수입니다. 상위 N개를 보여주는 것이 아니라 전부 나열합니다. 프로젝트마다 수치가 다른데, 예를 들어 OpenRA.Game 모듈은 5개, OpenRA.Mods.Common 모듈은 4개의 묶음이 있습니다.

각 항목을 클릭하면 그 묶음에 속한 구현 파일 FQN 목록이 펼쳐집니다. 묶음 안의 모든 구현 파일가 동일한 SCC에 있다는 사실 자체가 이미 위험 신호이므로, 점수가 낮은 구현 파일라도 함께 정리 대상이 됩니다.

Module Summary

구현 파일 G-SI의 파일별 최대값을 최상위 폴더(모듈) 단위로 집계한 표입니다. 상대 순위 요약이며 절대 품질이 아닙니다.

컬럼 의미

  • 모듈 — 분석 입력 폴더 바로 아래의 1단계 폴더 이름. 예를 들어 OpenRA.Game을 분석하면 Network, Server, Map 등이 모듈로 잡힙니다. (root)는 폴더 안에 들어있지 않고 분석 폴더 바로 밑에 놓인 C/C++ 구현 파일들을 한 모듈로 묶은 것입니다.
  • 등급 — 모듈 내 파일 최대 G-SI의 평균을 기준으로 한 A~E 구간.
  • 평균 G-SI — 각 파일의 si_max를 구한 뒤 파일별 동일 비중으로 평균. 구현 파일 전체 평균과 다릅니다.
  • 최대 G-SI — 모듈에서 가장 위험한 구현 파일 하나의 G-SI. 평균은 낮은데 최대만 높다면 그 모듈에 핀포인트 hotspot이 있다는 신호입니다.
  • 파일 수 · 구현 파일 수 — 모듈에 속한 선택한 구현 파일의 개수.

모듈 단위로 보면 어느 컴포넌트가 통째로 정리 대상인지, 아니면 특정 구현 파일만 문제인지 빠르게 판단할 수 있습니다.
